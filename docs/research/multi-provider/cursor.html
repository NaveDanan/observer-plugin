Cursor

Cursor gives T3 a clean, live model-and-options inventory through ACP. That is enough for a capable model picker. It does not establish an employee-level child control operation, so Observer should not advertise one.

ACP protocol v1live option discoverychild control unsupported

Verdict

Live
inventory

cursor/list_available_models returns models and each model's ACP config options.

5-step
selection order

Base model, reasoning, context, fast mode, then thinking. T3 applies mode last.

Root only
proven control

The inspected implementation configures one root ACP session. It does not steer a delegated child.

Recommended Observer status. Let users browse and store Cursor model choices by profile. Label employee child application as unsupported. Do not equate root-session ACP settings with a seated subagent.

Runtime and capability probe

  1. T3 runs cursor-agent about --format json, with a plain about fallback, to read version and login state.
  2. A gated preview path starts cursor-agent [-e endpoint] acp and sends ACP initialize.
  3. The client advertises parameterizedModelPicker: true, authenticates with cursor_login, and opens a temporary session.
  4. T3 calls the Cursor extension cursor/list_available_models, translates model-specific configOptions, then closes the scoped process.

Cursor supports multiple T3 instances. Each may have its own executable, endpoint, environment, credentials, and inventory. Observer should identify the target profile or instance before showing models.

The raw menu can change after a model change. T3 sets the base model, reads the refreshed options, then writes only selections supported by that model. Observer needs the same dependency-aware behavior instead of one global reasoning menu.

Application order and validation

session/set_config_option  model     = gpt-5.4
session/set_config_option  reasoning = extra-high
session/set_config_option  context   = 1m
session/set_config_option  fast      = true
session/set_config_option  thinking  = false
session/set_mode            mode      = implementation

The ACP runtime validates option types and select values against the current advertised state. Equal values are no-ops. Invalid model or option values fail before a request is sent. Cursor supports in-session root model changes through this config route.

A stored Cursor model must remain a bare host-owned ID plus typed options. Encoding options into a model string loses type information and turns changing provider metadata into parsing policy.

Why child control is not ready

  • Cursor documents a cursor/task extension notification with child metadata, including optional model and agent ID.
  • T3's Cursor adapter does not register or project that task extension in the inspected source.
  • The generic ACP runtime drops notifications for a session ID other than its root session until explicit lineage routing exists.
  • No Cursor request in this implementation sets model or reasoning for one delegated child.
Product boundary. A TUI can save a desired Cursor employee target, but it must show "not applied to delegated children" until Cursor exposes and Observer verifies a per-child control request. Silent root-session substitution would change the wrong actor.

Observer implementation notes

  1. Add a Cursor profile/instance target and live ACP inventory probe. Do not copy T3's preview date/channel gate as permanent protocol truth.
  2. Use typed option descriptors and selections. Preserve unknown ACP categories for future display, but apply only explicitly supported mappings.
  3. Refresh model-dependent options after base model selection. Clamp or clear invalid staged values before saving.
  4. Keep the current seat as desired configuration only. Report child control capability as unsupported.
  5. Add a Cursor host adapter only after real hook or ACP child fixtures establish stable identity, parentage, effective model, and control timing.
  6. Test bare IDs, grouped options, unknown categories, option changes after model switch, invalid values, login failure, process timeout, and multiple profiles.
