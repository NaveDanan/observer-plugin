Codex

Codex has the strongest non-OpenCode case for employee-level model and reasoning control. Its app-server protocol models child requests with explicit model and effort fields. Observer still needs a synchronous pre-spawn hook before it can use them.

Runtime and discovery

  1. T3 creates a scoped Codex driver instance. Its config includes binaryPath, homePath, optional shadowHomePath, launch args, environment, and custom models.
  2. The probe launches codex app-server, exchanges initialize and initialized, then calls account/read.
  3. When authentication permits, T3 paginates model/list and requests skills/list for the workspace.
  4. The driver publishes an instance-scoped snapshot. Multiple Codex accounts remain separate through ProviderInstanceId and their home layout.

A model is a Codex-owned slug. Account and home routing are a separate dimension. Observer's current hook payload has no T3 instance ID, so a native Observer seat cannot promise account selection without a profile mapping.

Child delegation

Codex app-server schemas expose child thread lineage and requested child settings. A collaboration tool item contains the sender thread, receiver thread IDs, prompt, optional model, optional reasoning effort, agent states, and lifecycle status. Child thread metadata can also include parent thread ID, nickname, role, depth, and path.

What is proven

  • Codex supports explicit child model and effort values.
  • An omitted value inherits according to Codex agent configuration rules.
  • Observer already receives post-creation Codex child hooks and observed model metadata.

What is missing

  • T3 does not mutate child spawns from an Observer seat.
  • Observer's emitter ignores daemon responses and writes no stdout.
  • No checked fixture proves the exact current spawn_agent input accepted by a Codex hook.

The control point must run before creation. A separate Codex control executable should handle only PreToolUse, validate the native spawn tool and full input object, change only model and effort, and return Codex's supported updatedInput response. Every error must leave the original input intact.

Observer implementation notes

  1. Add a Codex inventory adapter that probes app-server model/list, or consumes a trusted T3 snapshot. Cache by Codex profile, binary, home, and version.
  2. Represent the selected model as an opaque Codex slug and reasoning as option reasoningEffort. Preserve service tier as a separate option.
  3. Install the control hook into the selected Codex home or plugin scope, not only the default ~/.codex.
  4. Prototype a fail-open PreToolUse rewrite using captured real CLI fixtures. Do not use SubagentStart; the child already exists then.
  5. Keep configured and observed values separate. Record requested child effort only when the host reports it, with provenance.
  6. Expose control as experimental until tests cover neutral delegation, specialized-agent preservation, malformed input, timeout, unknown model, and host rejection.
