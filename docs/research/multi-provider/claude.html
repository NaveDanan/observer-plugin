Claude Code

Claude supports per-subagent model and effort in agent definitions. T3 proves rich root-session configuration and strong child attribution, but it does not generate employee definitions or steer child creation. Observer needs profile-aware discovery and a separate pre-tool control path.

Recommended Observer status. Add Claude as a host/profile target and support catalog browsing first. Keep child model control disabled until generated definitions and Agent input rewriting are verified against real Claude Code versions.

Runtime and profiles

T3's interactive Claude provider uses @anthropic-ai/claude-agent-sdk. It creates one long-lived query() per thread, feeds it an async prompt queue, consumes SDK messages, and uses query controls for model, permission mode, interruption, task stop, and close.

Model options are not one effort string

Claude's model ID is host-native. It may be an alias, a full Anthropic model ID, or a provider deployment ID. T3 can append [1m] for the context selection, but keeps context separate in its public model selection.

Effort

T3 uses option ID effort. It normalizes model/version compatibility, including xhigh fallbacks. ultracode maps to an effort plus settings. ultrathink is prompt text, not an API effort.

Other model traits

contextWindow, fastMode, and Haiku's thinking are independent. A single Observer variant field cannot represent this set.

Later-turn gap. T3 calls setModel() during an existing query and updates local effort attribution, but the inspected source does not prove that later effort, fast, thinking, or ultracode selections reconfigure the live query. Do not turn local bookkeeping into an "applied" claim.

Subagents and control

Claude's agent definition contract supports a model, effort, prompt, tools, skills, MCP servers, limits, background behavior, memory, and permission mode. Agent invocation can also carry a model override. T3 does not provide an agents map and does not create employee definitions.

Observation is strong

  • T3 links subagent messages through parent_tool_use_id.
  • It seeds task model and effort from the Agent call or root session.
  • It refines the child model from assistant.message.model.
  • Observer currently reconciles resolvedModel from the Agent/Task result.

Control remains unproven

  • SubagentStart can add context but cannot select a model before creation.
  • The current Observer emitter cannot return updatedInput.
  • A generated definition must preserve specialized prompts, tool limits, and permission policy.
  • Per-call effort is not a stable documented Agent input field.

The safest control design mirrors OpenCode's caution, not its file format. Generate marker-owned Claude definitions per employee and profile. Redirect only a verified neutral/default Agent invocation in a dedicated PreToolUse controller. Leave named specialized agents untouched.

Observer implementation notes

  1. Add Claude profile discovery with binary path, CLAUDE_CONFIG_DIR, version, and account status. Keep credentials outside Observer config.
  2. Use a Claude catalog adapter. Prefer a live SDK model inventory if the installed version supports it; fall back to a versioned list and free text.
  3. Persist an opaque model plus typed options. At minimum support effort, contextWindow, fastMode, and thinking when advertised.
  4. Improve observation before control. Capture common hook effort.level only when present and attach provenance.
  5. Prototype generated definitions and a synchronous Agent PreToolUse hook in the chosen profile. Copy all original Agent input and change only the selected neutral delegation field.
  6. Fail open on missing definitions, unsupported model options, timeout, or profile mismatch. Record diagnostics and preserve the original task.
