Runtime and authentication

command: grok
args:    agent stdio
cwd:     selected workspace
env:     instance environment + GROK_OAUTH2_REFERRER=t3code

T3 selects ACP auth method xai.api_key when XAI_API_KEY is non-empty, otherwise cached_token. Current status reporting still calls authentication unknown on both successful and failed discovery paths. Observer must not infer verified login from the presence of an environment variable.

The provider is disabled by default in T3. It runs grok --version, then opens a short-lived ACP runtime, performs initialize/auth/session setup, and reads sessionSetupResult.models.

Useful unmerged evidence

Reasoning branch

origin/t3code/audit-grok-build-gaps parses model _meta, advertises reasoningEffort, and sends it under session/set_model._meta. It also allows selected launch-time effort. None of this is in checked-out main.

Subagent branch

origin/t3code/grok-subagent-roster parses private xAI spawn and finish events and projects child task metadata. It observes a child model but provides no child model or effort setter.

Do not code to branch evidence as a public API. These branches reveal plausible option IDs and event shapes. They still need merge confirmation, released CLI support, capability negotiation, and captured transcripts.

Subagent boundary

  • Current GrokSessionContext owns one root ACP session and one active turn.
  • The shared ACP runtime rejects updates for another session ID until a provider implements lineage routing.
  • Current extension handling covers ask-user-question and prompt-completion messages, not subagent spawn or finish.
  • xAI hook documentation describes lifecycle notifications and allow/deny tool decisions, not a verified child input mutation contract.

A passive Grok Observer adapter is the next safe step. It should start with captured native hook fixtures, conservative model attribution, and explicit unknown parentage where signals are incomplete. Embedding a second ACP client in Observer would duplicate T3's runtime and still would not create a per-child setter.

Observer implementation notes

  1. Add a disabled-by-default Grok target with binary/profile identity and a scoped ACP model probe.
  2. Store a bare model ID. Do not prefix it with grok/ or treat a CLI alias as an API model ID.
  3. Expose no reasoning control for current main. If the reasoning work ships, read the advertised per-model values and use its host option ID.
  4. Do not mark a session/set_model request as effective model evidence. Wait for an authoritative host event or report it as requested only.
  5. Add native Grok hooks only from real fixtures. Keep child graph and child control capability false until stable IDs and lineage exist.
  6. Test disabled state, missing CLI, cached-token and API-key auth attempts, empty inventory, request failure, optimistic model state, and multiple profiles.
